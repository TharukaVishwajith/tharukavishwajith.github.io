කලින් Post එකේ අපි කතා කළේ AI යුගයේ Clean Code, Software Architecture සහ Engineering Principles තවත් වැදගත් වෙන ආකාරය ගැන. හැබැයි මේ කතාවේ තවත් පැත්තක් තියෙනවා. ඒ තමයි **Disposable Software (ඉවත දැමිය හැකි මෘදුකාංග)**.

AI නිසා දැන් අපිට පැය කිහිපයකින් අවශ්යතාවයකට ගැළපෙන Software එකක් හදාගන්න පුළුවන්. සමහර විට ඒක එක දවසකට, එක වැඩකට විතරක් භාවිත කරලා ඉවත් කරන්නත් පුළුවන්.

උදාහරණයක් විදිහට Personal Automation Script එකක්, One-time Data Analysis Tool එකක් හෝ කුඩා Event එකකට හදන Application එකක්.

> මේ වගේ Software එකකට අවුරුදු ගණනක් පවත්වාගෙන යන Banking System එකකට දෙන Engineering Effort එකම යොදවන්න අවශ්යද?

මෙතැනදී අපි සලකා බලන්න ඕන ප්රධාන කරුණු හතරක් තියෙනවා.

1. **Consequences of Failure** – Software එක Fail වුණොත් වෙන බලපෑම කොච්චරද?
2. **Dependencies** – කී දෙනෙක් සහ වෙනත් Systems කීයක් මේක මත රඳා පවතිනවද?
3. **Cost of Replacement** – අවශ්ය වුණොත් මේක නැවත හදන්න කොච්චර පහසුද?
4. **Cost of Maintenance** – දිගුකාලීනව Maintain කරන්න කොච්චර Effort එකක් අවශ්යද?

මේ හතරම ඉතා අඩු නම්, ඒක Disposable Software එකක් විදිහට සලකන්න පුළුවන්. එවැනි අවස්ථාවලදී අධික Engineering Complexity එකක් එකතු කරනවාට වඩා ඉක්මනින් අවශ්යතාව ඉටු කිරීම වැදගත් වෙන්න පුළුවන්.

හැබැයි Failure එකකින් ලොකු හානියක් වෙන, බොහෝ දෙනෙක් භාවිත කරන, දිගුකාලීනව පවත්වාගෙන යා යුතු **Durable Software** වලදී Code Quality සහ Architecture තවත් වැදගත් වෙනවා.

මෙය කළු-සුදු බෙදීමක් නෙවෙයි. Software එකක Disposability එක අනුව යොදවන Engineering Rigor එක තීරණය කරන්න ඕන. ඒ වගේම Disposable කියලා **Security හෝ Safety** නොසලකා හරින්නත් බැහැ.

**AI යුගයේ වැදගත්ම දේ හැම Software එකක්ම Perfect විදිහට Design කිරීම නෙවෙයි. කොයි Software එකට කොපමණ Engineering Effort එකක් අවශ්යද කියලා නිවැරදිව තීරණය කිරීමයි.**

ඒ වගේම AI Agents යොදාගෙන Software Develop කරන විට Code Quality එක පවත්වාගෙන යන්න AI Harness සහ Harness Engineering ඉතා වැදගත් වෙනවා. ඒ ගැන ඊළඟ Post එකෙන් කතා කරමු!
