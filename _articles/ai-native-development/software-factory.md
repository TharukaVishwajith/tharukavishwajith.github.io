අද AI Coding Agents භාවිතයෙන් අපිට Code ලියන්න, Tests Run කරන්න, Bugs Fix කරන්න සහ PRs නිර්මාණය කරන්න පුළුවන්.

නමුත් මේ හැම Task එකකටම අපි වෙන වෙනම Prompts ලබාදීලා Agents Manage කරන්න ඕනද?

ඒ වෙනුවට සම්පූර්ණ **Software Development Lifecycle (SDLC)** එක Automated Workflow එකක් විදිහට සැලසුම් කළොත්?

මෙතැනදී තමයි **AI Software Factory** කියන සංකල්පය වැදගත් වෙන්නේ.

## මොකක්ද Software Factory එකක්?

සරලව කිව්වොත්, Software Development Process එකේ විවිධ පියවර AI Agents, Automated Tools සහ Human Oversight එකට සම්බන්ධ කරලා, නැවත නැවත භාවිත කළ හැකි Workflow එකක් නිර්මාණය කිරීමයි.

උදාහරණයක් විදිහට:

> **Issue → Triage → Spec → Implement → Review → Verify → Deploy → Monitor**

මෙහිදී Triage Agent එකක් Task එක විශ්ලේෂණය කරනවා. අවශ්‍ය නම් Spec Agent එකක් Requirements පැහැදිලි කරනවා. Implementation Agent එක Code ලියනවා. Review සහ Verification Agents ප්‍රතිඵල පරීක්ෂා කරනවා.

අවදානම් සහිත අවස්ථාවල Human Approval ලබාගන්නත්, Deploy කළාට පස්සේ Monitoring හරහා හඳුනාගන්නා Issues නැවත Workflow එකට යොමු කරන්නත් පුළුවන්.

## AI Harness එකකට වඩා මෙය වෙනස් වෙන්නේ කොහොමද?

කලින් Post එකක අපි [AI Harness Engineering](/learn/ai-native-development/ai-harness-engineering/) ගැන කතා කළා.

**AI Harness** එකකින් Agent එකක් ක්‍රියාත්මක වීමට අවශ්‍ය Environment, Tools, Context සහ Execution Controls සපයනවා.

**Software Factory** එකකින් Planning සිට Deployment සහ Monitoring දක්වා Development Workflow එක Orchestrate කරනවා. ඒ සඳහා Harness එකක් හෝ කිහිපයක් භාවිත කරන්න පුළුවන්.

## Effective Software Factory එකකට අවශ්‍ය මොනවාද?

- **Automation** – Agents සහ Tools අතර Workflows Orchestrate කිරීම.
- **Context + Skills** – Project Knowledge, Rules සහ Reusable Skills ලබාදීම.
- **Human in the Loop** – වැදගත් තීරණ සහ අවදානම් සහිත වෙනස්කම් සඳහා Human Approval.
- **Self-Improvement** – Errors, Review Feedback සහ Performance අනුව Skills සහ Workflows වැඩිදියුණු කිරීම.

## Light Factory vs Dark Factory

Automation මට්ටම අනුව Software Factories ක්‍රියාත්මක කරන ආකාර දෙකක් ගැන හිතන්න පුළුවන්.

- **Light Factory** – AI Agents වැඩ කරන අතර Human Review සහ Approval ක්‍රියාවලියේ කොටසක් වෙනවා.
- **Dark Factory** – Code Generation, Review සහ Deployment වගේ ක්‍රියාවලීන් සාමාන්‍ය Human Intervention එකකින් තොරව ස්වයංක්‍රීයව සිදු වෙනවා.

නමුත් හැම Project එකක්ම සම්පූර්ණ Dark Factory එකක් බවට පත් කරන්න සුදුසු නැහැ.

කලින් Post එකේ කතා කළ [One-Way / Two-Way Door සහ Blast Radius](/learn/ai-native-development/review-tax/) වගේ සංකල්ප භාවිත කරලා, Low-Risk Changes වැඩි වශයෙන් Automate කරන්නත්, High-Risk Changes සඳහා Human Approval පවත්වාගන්නත් පුළුවන්.

ඒ නිසා බොහෝ අවස්ථාවල **Hybrid Approach** එකක් වඩාත් ප්‍රායෝගිකයි.

## Self-Improving Factory එකක් කියන්නේ මොකක්ද?

මෙහිදී Loops දෙකක් ගැන හිතන්න පුළුවන්.

- **Inner Loop** – Issues විසඳමින් Software Develop කිරීම.
- **Outer Loop** – Agent Failures, Review Feedback සහ Metrics භාවිතයෙන් Factory එකේ Skills, Rules සහ Workflows වැඩිදියුණු කිරීම.

ඒ කියන්නේ අපි Software එක විතරක් නොවෙයි, Software නිර්මාණය කරන පද්ධතියත් අඛණ්ඩව වැඩිදියුණු කරනවා. මෙවැනි වෙනස්කම් Validation සහ සුදුසු Human Oversight යටතේ සිදු විය යුතුයි.

## Software Engineers විදිහට අපේ අවධානය වෙනස් වෙන්නේ කොහොමද?

අපේ අරමුණ වැඩි Code හෝ PRs ප්‍රමාණයක් Generate කිරීම විතරක් නෙවෙයි. Software Quality පවත්වාගෙන යමින්, Human Time, Token Cost, Review Time සහ Rework Optimize කරලා වැඩි වටිනාකමක් ඇති Software Deliver කිරීමයි.

ඒ සඳහා Factory එකේ Performance මැනීමත්, අඩුපාඩු හඳුනාගෙන Workflows වැඩිදියුණු කිරීමත් වැදගත්.

**Software Factory Mindset** එකේ වැදගත්ම වෙනස මෙයයි.

අපි Software එක නිර්මාණය කරනවා විතරක් නෙවෙයි. **Software එක නිර්මාණය කරන පද්ධතියත් Engineer කරනවා.**

ඔබේ Project එකේ Software Development Workflow එකෙන් කොපමණ ප්‍රමාණයක් AI Agents භාවිතයෙන් Automate කරන්න පුළුවන් කියලා හිතනවද? ඔබේ අදහස් Comment එකකින් බෙදාගන්න.
